# Review rules

This file holds review-only rules for this repository. Code reviewers read it
next to `AGENTS.md`, with the same precedence. A reviewer reads this file as it
is at the merge base. A change to this file is changed text, and the review
checks it as such.

## Triggered checks

Each row comes from defects that closed plan reviews found in two or more
changes. Apply a row only when its trigger matches the diff. When a row supports
a finding, cite the row id as `check: T<n>` in the defect text of that finding.
Add or remove a row only as `plugins/docks/skills/AGENTS.md` (Adding a review
rule) says.

| Id | Trigger | Check | Source |
|---|---|---|---|
| T1 | The diff changes read-target, selector, list-split, or search-query handling in `.agents/skills/review-benchmark/scripts/score.mjs`, such as `pathTargets`, `delimitedParts`, `readLists`, `selectorRanges`, `readScope`, or the benchmark-query match. | The scorer reads each target as the omp `read` and search tools do. Check `;` and `,` lists, `:N`, `:N-M`, `:-N`, `:raw`, the context lines of a non-raw read, truncated lines, and `-site:` exclusions. Each target gets credit only for its own output. The expected count in a test matches the lines that a real tool result shows. | #100, #111, #119 |
| T2 | The diff adds or changes a shell block in `plugins/**/*.md`, a workflow `run:` step that a skill prescribes, or text that replaces a check command. | A tool error, a missing file, an empty match, or a warning does not read as a pass. Look for `!` before `grep`, `\|\|` fallbacks, exit statuses lost before `echo` or `diff`, `$(...)` that drops trailing newlines, and `errexit` or `pipefail` under `shell: bash`. A replacement gate keeps each check of the gate that it replaces. | #44, #123, #129 |
| T3 | The diff adds or changes an entry in `.agents/skills/review-benchmark/results.md`, or a summary that `score.mjs` reports. | The decision uses the cases, the statistics, and the rule that the plan fixed before the runs. Each figure and each arm description agrees with the setup and with the other sections. The entry records each repair, limit, and resolved ref that the plan asks for, and holds no placeholder. | #98, #100, #109, #113, #115 |
| T4 | The diff changes a regular expression or a function in `plugins/plan-lifecycle/skills/plan-manager/scripts/plan.mjs` that reads plan body text: sections, the Steps or Acceptance table, the Mode or delegation line, or the Goal comparison. | The scan runs on `blankFencedRegions` output and skips indented code lines. Two arms differ only in the variable that the comparison measures. A failed overlay or extraction stops with its cause. The scorer refuses a run whose transcript shows another configuration. | #100, #109, #113 |

| T8 | The diff changes text under `plugins/plan-lifecycle/` that tells an agent to run a `plan.mjs` command, set a plan status, archive a plan, or post a review block or verdict. | Read the refusal branches of that command, such as `setPlanStatus` or `archivePlan`. The `yolo` skill and the plan contract handle each verdict value that the text can produce. | #74, #83, #113, #115, #126 |
